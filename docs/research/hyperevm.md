# HyperEVM public RPC research

Reviewed 2026-11-06. Scope: HyperEVM mainnet (`999`, `0x3e7`) and testnet (`998`, `0x3e6`). This is a dated inventory, not a claim that every public endpoint on the internet has been found or that availability is permanent.

Discovery started with the sibling `smart-hyperevm/packages/smart-hyperevm/registry/nodes.json` snapshot from 2026-10-31, then checked current network and provider documentation. Live checks used unauthenticated HTTPS POSTs for `eth_chainId`, `eth_blockNumber`, and `eth_call` against HyperCore's L1 block-number precompile (`0x0000000000000000000000000000000000000809`, data `0x`, block `latest`). A passing precompile check returned a nonempty 32-byte word. No transactions were sent. These checks do not establish archive coverage, correctness of every method, or long-term uptime.

The initial sandbox could not resolve any RPC hostname. Approved network access allowed the probes below. Several initial requests with Python's default User-Agent received HTTP 403; subsequent requests with an explicit `smart-rpc-research/1.0` User-Agent passed. The table reports those completed checks, while retaining meaningful subsequent errors.

## Mainnet candidates suitable for the general pool

All ten endpoints below returned chain ID `999`, a current block height, and a valid HyperCore precompile result during this session. Numeric budgets in code are conservative client settings unless explicitly identified as published provider limits.

| Provider | Exact HTTP URL | Published restrictions and evidence |
| --- | --- | --- |
| Hyperliquid | `https://rpc.hyperliquid.xyz/evm` | Official endpoint. Published limit: 100 JSON-RPC requests/minute/IP. Keep the existing 1.5 rps, burst 3 budget. No official EVM WebSocket endpoint. [Network docs](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/hyperevm), [rate limits](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/rate-limits-and-user-limits). |
| HypurrScan | `https://rpc.hypurrscan.io` | Listed by the official network's tools directory; HTTPS worked in live checks. No numeric public limit verified. [Hyperliquid tools](https://hyperliquid.gitbook.io/hyperliquid-docs/builder-tools/hyperevm-tools). |
| dRPC | `https://hyperliquid.drpc.org` | Provider publishes the public URL. Public requests use a variable CU budget, up to three calls per batch, a two-second provider timeout, a 10,000-entry log limit, and disabled filter methods. Do not interpret the URL as a promise of archive/debug/trace/WSS availability. [Endpoint announcement](https://blog.drpc.org/drpc-adds-support-for-hyperliquid-rpc/), [limits](https://drpc.org/docs/howitworks/ratelimiting), [plan capabilities](https://drpc.org/docs/pricing/plans). |
| Purroof Group | `https://rpc.purroofgroup.com` | Provider explicitly offers a free archive RPC, subject to rate limiting without a published numeric ceiling. [Provider](https://www.purroofgroup.com/). |
| Stakely | `https://hyperliquid-json-rpc.stakely.io` | Public load balancer. Its upstreams include other public operators, so it is not fully independent infrastructure. No numeric public limit verified. [Provider](https://stakely.io/web3-api-load-balancer/hyperliquid). |
| OnFinality | `https://hyperliquid.api.onfinality.io/evm/public` | Provider publishes 5 req/s for anonymous access and lists archive support. An initial head/precompile pair passed; a later back-to-back identity/precompile pair produced HTTP 429 on the second call. Use a conservative burst and preserve Retry-After handling. [Provider](https://www.onfinality.io/en/networks/hyperliquid). |
| bloXroute | `https://hyperliquid.rpc.blxrbdn.com` | Published Fast RPC endpoint for chain 999; ordinary reads and precompile checks succeeded without authentication. No numeric public limit verified. Submission routing prioritizes propagation speed; it is not advertised as transaction privacy protection. [Provider](https://docs.bloxroute.com/core-solutions/rpc-service/fast-rpc). |
| PublicNode / Allnodes | `https://hyperliquid-rpc.publicnode.com` | Provider's main page includes Hyperliquid and this exact URL in its embedded endpoint registry. Identity, head, and precompile passed. No numeric public limit verified. [Provider](https://publicnode.com/). |
| Pocket Network | `https://hyperliquid.api.pocket.network` | Listed in the provider's public endpoint directory; keyless fair-use access. The supported-chains guide states a 2,000 requests/minute/IP limit. [Provider directory](https://docs.pocket.network/developers/supported-chains/), [public portal](https://api.pocket.network/). |
| Web3CDN | `https://hyperliquid.web3cdn.rest` | Identity, head, and precompile passed. Provider publishes no-key limits of 2/s, 60/min, 1,000/hour, and 10,000/day. Included with a deliberately low client budget of 0.025 rps, burst 2, shared in policy with the Ethereum and two Solana Web3CDN defaults. [Provider](https://web3cdn.network/rpc/hyperliquid). |

The five preexisting eligible sibling providers remain useful. OnFinality and bloXroute had no successes in the older sibling snapshot but responded successfully in this session; historical eligibility must not be confused with current results.

With one pool for each of the four Web3CDN default network URLs, the configured budgets allow 8,640 requests/day plus eight initial burst tokens, and 360 requests/hour plus those initial tokens. These are process-local token buckets, not shared-IP quota tracking. Additional pools, processes, applications, explicit overrides, and traffic outside this library can consume the same provider allowance. Probe token reservation leaves capacity for user requests at this low rate.

## Other free public mainnet endpoints

These URLs are real candidates, but daily quotas, method restrictions, or failed checks make them inappropriate as unrestricted defaults. They can remain documented or be explicitly configured with the relevant restrictions.

| Provider | Exact URL | Result and limitation |
| --- | --- | --- |
| 1RPC | `https://public.1rpc.io/hyperliquid` | Identity, head, and precompile passed. Current docs specify 200 requests/user/day, then blocking until UTC midnight. A 4-second probe loop alone can consume that quota in roughly 13 minutes of continuous activity. Keep opt-in unless daily/probe accounting is added. [Network page](https://www.1rpc.io/ecosystem/hyperevm), [quota docs](https://docs.1rpc.io/using-the-web3-api/errors). |
| MoltNode | `https://moltnode.ag/hyperevm` | Identity, head, and precompile passed. Current homepage: 2,000 requests/day/IP, burst 60 then 3/s, 8 MB response cap. Daily quota is unsuitable for unrestricted health probing. Provider page currently advertises one upstream for this chain, so it adds limited independence. [Chain page](https://moltnode.ag/hyperevm), [current quotas](https://moltnode.ag/). |
| Tatum / FREERPC | `https://hyperevm-mainnet.gateway.tatum.io` | Identity and head passed. `eth_call` returned JSON-RPC `-16401`, explicitly requiring a paid plan, including for the HyperCore probe. Free endpoint advertises 5 requests/minute. Any use must block `eth_call`, respect that low rate, and account for probe consumption. [Free gateway](https://freerpc.com/hyperevm), [provider](https://tatum.io/chain/hyperevm). |
| NodeFlare | `https://rpc.nodeflare.app/hl/public` | Identity, head, and precompile passed when requests were separated by more than 10 seconds. Closer requests returned HTTP 429. Published limit: one request/10 seconds/IP; heavy methods, including `eth_getLogs`, filter methods, tracing and debugging, require a key. [Provider](https://nodeflare.app/chains/hyperliquid), [public method limits](https://nodeflare.app/chains). |
| RouteMesh | `https://lb.routeme.sh/rpc/evm/999` | Provider documents a free keyless community route, but both live head/precompile checks returned HTTP 429 requesting signup. Do not classify it as live-verified or enable it by default based only on the directory. [Provider](https://routeme.sh/chain/evm/999-hyperevm). |
| HyperLend | `https://rpc.hyperlend.finance` | Head passed; HyperCore precompile returned an out-of-gas error (HTTP 503). Provider documents 30 req/s/IP and a 50-block log range. Preserve exclusion for a general HyperEVM transport because the current per-method capability hook cannot distinguish precompile `eth_call`s from ordinary `eth_call`s. [Provider](https://docs.hyperlend.finance/developer-documentation/data-and-indexers). |
| HyperLend archive | `https://rpc.hyperlend.finance/archive` | Identity passed; the same HyperCore precompile failed with JSON-RPC `-32003` out-of-gas. Provider describes Nanoreth archive nodes. The archive suffix does not fix precompile compatibility. [Provider](https://docs.hyperlend.finance/developer-documentation/data-and-indexers). |
| Sentio | `https://hyperevm.rpc.sentio.xyz` | Existing sibling candidate. Head passed; precompile returned JSON-RPC `-32003` out-of-gas. No current provider page establishing the exact public endpoint was located. Exclude until both provenance and HyperCore compatibility are resolved. |
| BlockReq | `https://hyperevm-rpc.blockreq.com/v1/rpc/public` | Identity, head, and precompile passed. Provider characterizes public endpoints as a restricted trial with recent-state access and an unspecified shared IP limit. HyperEVM precompiles support `latest` only; proof/debug/trace are not guaranteed. Kept opt-in pending clearer anonymous capability and quota guarantees. [HyperEVM docs](https://blockreq.com/docs/build/api-reference/hyperevm/), [public endpoint policy](https://blockreq.com/docs/build/public-endpoints/), [trial behavior](https://blockreq.com/docs/build/ai-assistants/). |
| BlockVectra | `https://api.blockvectra.com/v1/hyperevm_mainnet/public` | Identity and head passed; HyperCore precompile failed out-of-gas. Public route is read-only, excludes `eth_getLogs`, and exposes only the latest 1,000 blocks; 3 req/s/IP, burst 20, batch maximum 10. Exclude from the general pool. [Provider](https://blockvectra.com/en/free/), [HyperEVM limitations](https://docs.blockvectra.com/en/guides/hyperevm-backfill/). |
| thirdweb | `https://999.rpc.thirdweb.com` | Naked URL is listed on the provider's chain page and passed all three checks. However, the infrastructure access policy requires an API key, and current client docs describe URLs with a client ID. Do not treat a currently responsive naked route as permission for a default keyless integration. [Chain page](https://thirdweb.com/HyperEVM), [API-key policy](https://blog.thirdweb.com/changelog/api-keys-to-access-thirdweb-infra/), [current client docs](https://portal.thirdweb.com/typescript/v5/client). |

Tatum's current [gateway capability matrix](https://docs.tatum.io/docs/gateway-limits) confirms that anonymous and free-key plans exclude `eth_call`, `eth_callMany`, `trace_call`, `trace_callMany`, `debug_traceCall`, and `eth_simulateV1`. Anonymous `eth_getLogs` is capped at 100 blocks. A free API key does not remove these call-method restrictions. These constraints plus the low anonymous rate make Tatum a partial opt-in endpoint rather than a general HyperEVM fallback.
