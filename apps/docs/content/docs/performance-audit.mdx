**Follow-up, November 27, 2026.** A second pass targeted the two chains whose router was slower than its best endpoint. Raw results are in `reports/performance/2026-11-27/`. All figures are small samples from one location.

| Chain | Best direct read p50 | Router p50 before | Router p50 after | Router p95 before | Router p95 after |
| --- | ---: | ---: | ---: | ---: | ---: |
| hyperevm | 89 ms | 561 ms | 122 ms | 875 ms | 243 ms |
| solana | 66 ms | 110 ms | 125 ms | 824 ms | 393 ms |

The 60-request HyperEVM workload finished in 3.1 seconds instead of 8.3, and Solana's in 3.2 instead of 10.4, because requests no longer queue for budget tokens. Solana's p50 did not improve: its two fast keyless endpoints are the whole pool, and a production deployment needs a keyed endpoint beside them. Three Ethereum runs on unchanged routing code measured 47, 86 and 48 ms, so differences of that size between single runs are noise.

Three causes were addressed. HyperEVM's community endpoints were held to a self-imposed 1 request/second; five of six candidates answered 300 of 300 reads at 5 requests/second for 60 seconds, so their budgets rose to 3–4 requests/second (Stakely drew HTTP 429 after about 33 seconds and stays at 1). HyperEVM registry weights divided the score permanently, which ranked a 450ms established node ahead of 120ms nodes with capped weights; weights are now priors that fade over five live samples. Solana Vibe Station timed out on every connection and was removed, and the remaining Solana budgets were raised within the published and measured limits. Purroof Group was added to HyperEVM. Base and Ethereum already routed within 5% of their best endpoint and are unchanged.

Candidates measured and not added: bloXroute (no documented permission for unauthenticated use; its Ethereum host is a private-mempool product), Nodies (hostnames not found in provider documentation; no CORS preflight), `mainnet-preconf.base.org` (Flashblocks retired), and every keyless Solana candidate (rate-limited, paid-only or discontinued).


**Release integration follow-up:** the combined 0.3.0 registries contain **105 active defaults across 25 networks**, all passing a fresh identity check and three head, balance, and EVM call samples per endpoint. Results are in `reports/performance/2026-11-17/release-endpoints.json`. The merge includes the earlier audit’s five documented replacements and removes its additional stale defaults. HyperEVM’s log probe now respects each provider’s declared range cap; dRPC passed within its 100-block cap and is restored as a low-weight fallback. PublicNode remains first for ordered cold starts.

The measurements below describe the optimization pass before release integration. That snapshot retained 102 active endpoints and one disabled HyperEVM candidate. Eight unsuitable defaults were removed, startup order was improved on ten mainnets, and HyperEVM’s rolling history was refreshed.

The original 111 candidates produced 109 passes with the old identity/head check. Adding repeated balance reads reduced that to 104. Adding EVM `eth_call` exposed further method-specific failures. The final membership was selected from the complete expanded audit, without discarding any failed sample for a retained endpoint. Raw successful and failed observations are preserved under `reports/performance/2026-11-17/`.

**Library CPU improvements.** Cache keys now avoid intermediate fragment arrays; repeated access to the newest cache entry avoids redundant Map updates; cached logs are copied once on return while preserving input/output isolation.

| Workload | Before, ops/CPU-second | After, ops/CPU-second | Change |
| --- | ---: | ---: | ---: |
| One hot cache key | 579,882 | 704,800 | +21.5% |
| 64 rotating cache keys | 955,797 | 998,594 | +4.5% |
| EVM cache-plan generation | 1,447,486 | 1,676,241 | +15.8% |
| Cached queries returning 1,000 logs | 4,979 | 9,843 | +97.7% |

Node 24.22.1, macOS arm64, one process with alternating before/after implementations: nine pairs for cache and plans, seven for mixed keys, five for cached logs. These are medians normalized by process CPU time, not network requests per second. Other applications were building concurrently on this Mac, so wall-clock throughput was noisy; the small mixed-key change should be treated as approximately neutral. The unchanged direct log-index workload also varied with machine load. Baselines include the pre-existing workspace edits, identified in `metadata.json`.

**Removed defaults and evidence.** Explicit user-supplied endpoints remain supported.

| Network / provider | Finding |
| --- | --- |
| Solana mainnet and devnet / Tatum | Both retested with slower pacing; `getBalance` repeatedly returned paid-plan errors. |
| Plasma / Tatum | Public requests hit HTTP 429; anonymous EVM `eth_call` is restricted by plan. |
| Solana testnet / Web3CDN | Two 5-second identity timeouts, followed by a network error on a 15-second retest. This establishes failure from this client, not a worldwide outage. |
| Etherlink / dRPC | Identity succeeded, but head and balance reads repeatedly returned HTTP 400. |
| opBNB / dRPC | Five of eight balance reads failed with HTTP 408 across the first two sampled rounds. A later round recovered; the endpoint stays excluded pending sustained health. |
| Mantle / dRPC | Intermittent balance failures plus three of five empty calls timing out with HTTP 408 in the expanded round. |
| Polygon / ZAN | Head and balance succeeded, but `eth_call` returned HTTP 403 in both independent rounds. |

Tatum’s [published method restrictions](https://docs.tatum.io/docs/gateway-limits) confirm the paid-plan requirement for Solana balances/account queries and EVM calls. An authenticated endpoint with an appropriate plan is an explicit configuration choice.

**HyperEVM cold-start follow-up.** The first optimization pass left HyperEVM’s cold request around 1.27 seconds: historical weights selected Hypurrscan ahead of the faster eligible registry leaders. Fresh default pools now use `coldStart: "ordered"` until a request-latency sample or restored score exists. This temporarily uses neutral weights and the curated order, while retaining identity verification, budgets, health, and capability checks. Normal historical weighting resumes after the first sampled request. Explicit endpoints retain weighted startup unless the caller opts in.

An alternating A/B comparison with a fresh Node process and HTTP connection pool for every sample measured:

| First request | Weighted startup p50 | Ordered startup p50 | Reduction |
| --- | ---: | ---: | ---: |
| `eth_getBalance` | 1,378 ms | 561 ms | 59% |
| Empty `eth_call` | 1,352 ms | 390 ms | 71% |

Each cell contains five live samples from one location. Timing includes pool construction, live identity verification, and the read, but excludes module import/process startup. Run `node scripts/benchmark-hyperevm-startup.mjs --runs 5` or add `--method eth_call` to repeat the comparison. Request timelines and full results are saved in `reports/performance/2026-11-17/hyperevm-startup/`. Set `coldStart: "weighted"` to retain the previous first-call policy.

**Remaining performance limits.** The historical registry weights and eligibility rules still apply after startup. The registry refresh enabled PublicNode and disabled mainnet dRPC after another realistic log-range failure. HyperEVM Stakely measured 842 ms median balance latency in the initial sampled round and remains a slow alternative. Reuse a pool to retain its verified identities and connections across requests.

Robinhood’s official endpoint measured roughly 1.14 seconds for balance reads; Gnosis’s official endpoint about 612 ms; Flare’s official endpoint about 592 ms. They remain lower-priority fallbacks behind measured faster providers. Pocket commonly measured around 180–220 ms for state and 700–770 ms for initial identity/TLS requests. Solana devnet now has one verified keyless default, so applications requiring redundancy need an explicitly configured additional provider.

**Scope and reproduction.** The audit made no transactions. EVM reads used `eth_chainId`, `eth_blockNumber`, `eth_getBalance` at `latest`, and an empty `eth_call` to the zero address. Solana used `getGenesisHash`, `getSlot`, and `getBalance` at `processed`. An empty call verifies method access, not complex contract execution, archive queries, logs, WebSockets, batch support, or all precompiles. HyperEVM’s separate existing probe additionally checked logs and its HyperCore precompile.

The expanded endpoint run was 2026-11-17T11:04:12.420Z through 2026-11-17T11:10:39.320Z. Request p50/p95 excludes provider pacing but includes HTTP/body validation. Identity is the cold connection request; later samples reuse connections. Five-sample p95 is effectively the slowest successful sample, not a reliable production tail estimate. Failures and attempt counts remain visible in the JSON. Single-location measurements do not establish global speed or future uptime.
